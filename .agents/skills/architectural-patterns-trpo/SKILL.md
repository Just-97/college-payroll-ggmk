# Архитектурные паттерны ТРПО (MVC, MVP, MVVM)

Данный скилл определяет строгие стандарты разделения ответственности (**Separation of Concerns**), инверсии зависимостей (**Dependency Inversion**) и применения архитектурных паттернов **MVC**, **MVP** и **MVVM** в кодовой базе проекта.

---

## 1. Паттерн MVC (Model-View-Controller)
Используется для управления состоянием, сущностями с CRUD-операциями и административными панелями.

### Правила распределения ролей:
* **Model (Модель):**
  * Единственный источник истины для сущности данных.
  * Реализует паттерн **Observer (Наблюдатель)**: методы `subscribe(listener)`, `unsubscribe(listener)` и `notify()`.
  * Инкапсулирует валидацию полей сущности (формат email, сложность пароля, допустимость ролей).
  * Выполняет запросы к БД / LocalStorage без привязки к компонентам UI.
* **View (Представление):**
  * Подписывается на Модель через хук подписки или `useEffect`.
  * Отображает текущее состояние Модели.
  * При возникновении пользовательских событий (нажатие кнопок, отправка формы) **не меняет модель напрямую**, а вызывает соответствующие методы Контроллера.
* **Controller (Контроллер):**
  * Принимает пользовательский ввод от Представления.
  * Проверяет бизнес-условия (наличие прав, валидность параметров действия).
  * Вызывает мутирующие методы Модели.

## 2. Паттерн MVP (Model-View-Presenter)
Используется для персональных отчетов, расчетных листков преподавателей и печатных документов (А4).

### Правила распределения ролей:
* **Passive View (Пассивный вид):**
  * Строго описывается через контракт **TypeScript Interface** (например, `IPayslipView`).
  * Представление реализует методы интерфейса: `renderPayslip(dto)`, `setLoading(state)`, `showError(message)`, `executeBrowserPrint()`.
  * В коде View **запрещено** выполнять расчеты налогов, форматирование сумм или бизнес-логику.
* **Presenter (Представитель):**
  * Связан с конкретным View отношением 1-к-1.
  * Знает только интерфейс `IPayslipView`, но **не знает о React, DOM или HTML**.
  * Извлекает сырые данные из Модели, выполняет все расчеты (подоходный налог 13%, взносы ФСЗН 1%, профвзнос 1%, округление копеек по правилам РБ), форматирует вывод ("BYN", даты) и передает готовый DTO в метод `view.renderPayslip(...)`.
  * *Критерий качества:* Presenter должен быть на 100% покрываем юнит-тестами без запуска браузера и без React Testing Library.
* **Model (Модель):**
  * Хранит исторические начисления, профили преподавателей и базовые тарифные ставки.

## 3. Паттерн MVVM (Model-View-ViewModel)
Используется для аналитических панелей, рабочего места бухгалтера, сводных ведомостей и таблиц с динамической фильтрацией.

### Правила распределения ролей:
* **Model (Модель):**
  * Репозиторий доменных данных (ведомости колледжа, тарифная сетка, норма часов 720 ч/год).
* **ViewModel (Модель представления):**
  * Реализуется как кастомный реактивный хук (например, `useAccountantViewModel()`) или Observable класс.
  * Предоставляет **Two-Way Data Binding** (свойства состояния и сеттеры для двухстороннего связывания с элементами ввода).
  * Содержит **Computed Properties (Вычисляемые свойства)** через `useMemo` (суммарный фонд заработной платы, удержания по колледжу, отфильтрованный список записей).
  * Инкапсулирует **Commands (Команды)**: методы действия пользователя (`savePayrollCommand`, `deletePayrollCommand`, `exportCsvCommand`).
* **View (Представление):**
  * Декларативно привязывается к свойствам и командам ViewModel.
  * Не содержит алгоритмов фильтрации или агрегации данных.

## 4. Чек-лист проверки при код-ревью
1. [ ] Во View нет прямых расчетов формул заработной платы и налогов?
2. [ ] В MVP логика форматирования полностью вынесена в Presenter?
3. [ ] В MVP интерфейс `I...View` не содержит типов из React (`ReactNode`, `JSX.Element`)?
4. [ ] Во ViewModel все фильтрации и суммы мемоизированы (`useMemo`)?
5. [ ] В MVC модель уведомляет слушателей через Observer?
6. [ ] Все сущности соответствуют домену УО «ГГМК» и законодательству РБ (базовая ставка 270 BYN, годовая норма 720 ч)?
